# Journey component status

This matrix describes repository functionality. It does not establish which agents, services or models are installed or running on HEXSEED. The integration candidate is under development review in pull request 8; no production deployment or merge is authorized by these results.

| Component | Status | Demonstrated capability and limit | Needed for the collection workflow? |
| --- | --- | --- | --- |
| Standalone Folder Planner and stewardship contract demo | Existing public source workflows | Scoped inventory, collections, naming/placement previews and contract inspection. These are separate entry points; their presence does not certify the integrated runtime. | No additional entry point needed |
| Navigator inspection | Integration candidate | Selected-scope inventory, image features, readable image text, coverage and scoped corrections. Metadata drift or incomplete coverage can leave gaps. | Yes |
| Project pack and naming registry | Integration candidate | Explicit activation of project-specific evidence and rules. Only substantiated rules can produce executable naming proposals. Full CareBloomOS filename grammar remains open. | Yes for project-specific context |
| Archive history | Integration candidate | Separately authorized native-export ingestion, attributed structured claims, overlap handling, candidate references and unresolved conflicts. It does not retain a complete general conversational memory model. | Optional evidence enrichment; demonstrated explicitly in the fixture |
| Incremental reconciliation | Integration candidate | Preserves observations and accepted corrections; refreshes affected saved interpretations. Historical attachment pointers do not provide file bytes. | Yes when adding evidence to prior work |
| Guided collection path and saved preview | Integration candidate | Reuses Inspect, project/history controls, Destination, Patrol and review export. The result is evidence-linked virtual organization with open questions. Navigation is not confirmation of canon. | Yes |
| Guided physical operations | Integration candidate with separate authority | Exact reviewed batches, Windows-account approval, freshness checks, receipts and guarded reversal. A preview or model answer provides no operation authority. | No physical operations needed to complete the demonstrated preview |
| Drift and archive monitoring | Integration candidate, opt-in and session-only | Bounded metadata/import work and virtual reconciliation within the granted scope. Starts off after restart. | No |
| Qwen3 adapter via existing Ollama service | Experimental optional interpretation | Fixed loopback endpoint, `qwen3:4b`, one request at a time, bounded response, and a narrow Find/Organize/Retire vocabulary. It receives the live instruction and schema; historical exports and file bytes are not sent through this adapter. It has no tools or execution authority. | No; deterministic commands cover this workflow |
| Pillow image analysis | Existing dependency used by candidate | Local image decoding, features and thumbnails. These visual features do not constitute general semantic image understanding. | Yes, already packaged |
| Tesseract English text reader | Existing packaged optional perception capability | Reads text from authorized image pixels, with explicit unreadable, retry and timeout states. It is not a general agent or conversational model. | Useful for image text; filename/history evidence still works without it |
| General capability dispatcher, multi-agent coordination and broader adaptive memory | Planned architecture | Existing capability contracts, governance and provenance machinery provide foundations. They do not demonstrate general autonomous tool orchestration or a self-improving steward. | No additional framework is justified for this milestone |
| Continuous maintenance across sessions, standing physical authority, automatic build cleanup | Planned or held | Not implemented or authorized as unattended production work. Existing preservation and recovery boundaries remain binding. | No |
| Live HEXSEED operation and accessibility task completion | Unverified | Hosted Windows fixtures are distinct from the owner's account, real collections, local-model responsiveness, screen-reader and alternative-input task completion. | Separate authorized acceptance is required |

No dependency, model download, service installation or separate interface is added for this collection milestone. Future agent capabilities remain in the forward architecture and are not removed to simplify this workflow.
