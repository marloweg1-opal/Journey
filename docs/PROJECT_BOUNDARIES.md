# Project Boundaries

Journey is a project-neutral local stewardship and orchestration system.

## Journey owns

- functional kernels and stable capability contracts
- observation, classification, proposal, approval, receipt and undo mechanics
- project-profile interfaces and validation
- generic asset-intake and routing machinery
- Navigator behavior and system-wide safety policy

## Integrating projects own

- project-specific terminology and doctrine
- identity artwork, icons, frames and source assets
- project-only cleanup, migration and consolidation scripts
- domain handoffs, canon and presentation decisions
- their canonical source trees and release history

## Integration rule

An integrating project may translate Journey's functional kernels into its own
language and presentation. That translation is a profile, not Journey's base
ontology. Journey may keep a small fixture or example needed to verify the
profile contract; the project's durable implementation remains with the project.

[CareBloomOS](https://github.com/marloweg1-opal/CareBloomOS) is also a **separate family passion project**: an original, character-driven fantasy desktop experience built around care, childhood wonder, magic, friendship, Saturday-morning-cartoon nostalgia, Carestone Bearers and their lore. It is not a Journey subsystem or a mere skin on Journey, and Journey is not CareBloom's operating system. Both developed alongside earlier HEXSEED organization and personalization efforts; their later boundaries emerged from experience rather than being imposed retroactively on that history.

CareBloomOS supplied Journey's first mature documented integration profile. Journey retains only the minimal example/fixtures needed to express or test that **generic profile contract**. The example does not certify a complete CareBloom/Journey runtime integration. CareBloom-specific worldbuilding, source artwork, icons, canon, handoffs and project-only operational scripts belong to CareBloomOS and its own repository. Journey's core implementation, permissions, receipts and recovery policy belong to Journey. Sharing a creative/technical family does not transfer project ownership or authority.
